## The Five Main Windows Event Logs

Windows organizes its event data into several log categories. Each category records a different type of system activity and provides valuable information for administrators and security analysts.

| Log Name | What it Records | Why a SOC Analyst Cares |
|----------|-----------------|-------------------------|
| **Application** | Events generated by applications such as software errors, warnings, crashes, and informational messages. | Helps identify application failures, malware crashes, and suspicious application behavior. |
| **Security** | Authentication events, user logins and logouts, account creation, privilege changes, and audit events. | One of the most important logs for security monitoring, incident response, and threat hunting. |
| **System** | Events generated by Windows, device drivers, hardware components, and core system services. | Useful for identifying system failures, unexpected reboots, driver issues, and service-related problems. |
| **Setup** | Operating system installation, Windows updates, and configuration changes. | Helps determine when software or system updates were installed and can assist during forensic investigations. |
| **Forwarded Events** | Events collected from remote Windows systems using Windows Event Forwarding (WEF). | Allows analysts to monitor multiple computers from a central location, improving visibility across an environment. |

---

## Why These Logs Matter

Each log provides a different perspective of what is happening on a Windows system. Together, they create a comprehensive record of system activity that can be used for troubleshooting, security monitoring, and incident investigations.

Among these logs, the **Security** log is the most valuable for SOC analysts because it contains information about authentication, account management, privilege changes, and other security-related events. During an investigation, analysts often correlate events from the Security, System, and Application logs to reconstruct an attack timeline and understand the sequence of events.
# Event Viewer

## What is Event Viewer?

Event Viewer is a built-in Windows utility that allows users to view, search, and analyze Windows Event Logs. It provides a centralized interface for monitoring system activity, troubleshooting issues, and investigating security-related events.

System administrators and SOC analysts use Event Viewer to examine logs generated by Windows, applications, and security components to identify suspicious behavior, diagnose problems, and reconstruct incident timelines.

---

## Accessing Event Viewer

There are several ways to open Event Viewer:

1. Press **Win + R**, type `eventvwr.msc`, and press **Enter**.
2. Search for **Event Viewer** in the Windows Start Menu.
3. Right-click the Start button and select **Event Viewer**.

Event Viewer is one of the first tools used during security investigations. It enables analysts to:

- Investigate application crashes.

Although modern SOCs typically collect logs into a SIEM, understanding how to use Event Viewer is essential because it is the original source of Windows Event Logs.
# Common Windows Security Event IDs

Windows assigns a unique Event ID to every recorded event. These Event IDs allow administrators and security analysts to quickly identify what activity occurred on a system.

Understanding common Event IDs is a fundamental skill for SOC analysts because they are frequently used during security monitoring, threat hunting, and incident response.

---

## Frequently Used Security Event IDs

| Event ID | Event | Why It Matters |
|----------|-------|----------------|
| **4624** | Successful Logon | Records successful user authentication. Useful for tracking user activity and identifying unusual login patterns. |
| **4625** | Failed Logon | Indicates an unsuccessful login attempt. Multiple failed logons may suggest brute-force attacks or password guessing. |
| **4634** | Logoff | Records when a user logs off the system. Helps build user activity timelines. |
| **4648** | Logon Using Explicit Credentials | Indicates a user or process attempted authentication using alternate credentials. Can reveal lateral movement techniques. |
| **4672** | Special Privileges Assigned | Generated when an administrative account logs in. Useful for monitoring privileged account activity. |
| **4688** | Process Creation | Records when a new process starts. One of the most valuable events for detecting malicious activity. |
| **4697** | Service Installed | Indicates a new Windows service has been installed. Malware often creates services to maintain persistence. |
| **4720** | User Account Created | Records the creation of a new user account. Important for detecting unauthorized account creation. |
| **4726** | User Account Deleted | Indicates a user account has been removed from the system. |
| **4732** | User Added to Security Group | Shows when a user is added to a privileged group, such as Administrators. |
| **4740** | User Account Locked Out | Records account lockouts, often associated with repeated failed login attempts. |
| **4768** | Kerberos Authentication Ticket (TGT) Requested | Used in Active Directory environments to monitor Kerberos authentication activity. |
| **4769** | Kerberos Service Ticket Requested | Helps detect unusual service ticket requests and potential Kerberoasting attacks. |
| **4776** | NTLM Authentication | Records NTLM authentication attempts. Useful for identifying legacy authentication and suspicious login behavior. |
| **1102** | Security Log Cleared | Indicates that the Windows Security Log was cleared. This is a high-priority event because attackers may erase logs to hide their activity. |

---

## Why These Event IDs Matter

Security Event IDs provide visibility into authentication, process execution, account management, privilege changes, and system modifications. During an investigation, SOC analysts rarely rely on a single event. Instead, they correlate multiple Event IDs to reconstruct the sequence of events and understand what occurred on the system.

For example:

1. **4625** – Multiple failed login attempts.
2. **4624** – A successful login immediately afterward.
3. **4672** – Administrative privileges assigned.
4. **4688** – A suspicious process is launched.
5. **1102** – The Security log is cleared.

Viewed together, these events could indicate a successful compromise followed by privilege escalation, malicious execution, and an attempt to remove evidence.
# Conclusion

Windows Event Logs are one of the most important sources of information for monitoring and investigating Windows systems. They provide detailed records of authentication events, system activity, application behavior, and configuration changes.

For SOC analysts, understanding Windows Event Logs is a foundational skill. Whether investigating security incidents, hunting for threats, or monitoring enterprise environments, the ability to interpret event data is essential.

As security environments become more advanced, tools such as Sysmon, Windows Event Forwarding (WEF), and Security Information and Event Management (SIEM) platforms build upon these native logs to provide deeper visibility and centralized analysis. Mastering Windows Event Logs is therefore the first step toward effective detection engineering and incident response.
